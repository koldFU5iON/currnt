# Application Documents

## What this part is for

CVs and cover letters are different forms of the same work: presenting a truthful, relevant professional story for a particular opportunity.

They should live in one shared document workspace. The user should not have to learn one editing experience for CVs and another for cover letters, nor should AI treat one as structured data and the other as an opaque block of text.

## The shared workspace

The workspace should make the job, [[Job Tracking and Assessment|assessment]], selected [[00 Foundations/Working Language#Evidence|evidence]], document, and final output visible together without becoming crowded.

It should support:

- Direct editing where the user is looking.
- Clear document structure without trapping the user in forms.
- Reordering, including or excluding content, and changing emphasis.
- AI suggestions that can be reviewed one at a time.
- A clear difference between a suggestion, an accepted edit, and original user content.
- A reliable final page view before export.

The user should feel they are editing a document, not operating a set of unrelated controls.

## CV

A CV needs structure because it is dense and has consequences for hierarchy, relevance, and page length. It should make it easy to work at both levels:

- The story level: which experience, capabilities, and outcomes deserve space for this job?
- The sentence level: is each claim accurate, clear, specific, and supported?

The document should not be regenerated wholesale whenever the user asks for help. AI changes should be narrow, visible proposals: revise this outcome, shorten this section, surface evidence for this requirement, or suggest a different ordering.

## Cover letter

A cover letter needs room for voice and judgment, but it still benefits from the same evidence and assessment context as the CV.

It should be simpler and more conversational to write, while retaining a visible structure: opening, argument, examples, and close. The user should be able to write from scratch, use a draft as a starting point, or ask for targeted feedback without surrendering the whole letter to a replacement draft.

## PDF and page confidence

What the user sees while editing should be a trustworthy representation of what they will export.

The product should make page size, margins, page count, and likely page breaks understandable before download. It should help the user resolve awkward splits and overflow instead of discovering them after the fact.

PDF is not a separate afterthought. It is the final form of the document workspace.

## How it should feel

- Editorial, focused, and unhurried.
- Precise enough for a high-stakes document.
- Supportive without taking authorship away from the user.
- Confident in layout, not full of hidden export surprises.
- Consistent whether the user is working on a CV or a cover letter.
