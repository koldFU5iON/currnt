# Flow and Responsive Principles

## Start with flow, not screens

Before defining page layouts or visual style, currnt needs to establish how a user moves through their career information and how that movement changes by device.

The product should not begin with a desktop vault and attempt to shrink it for mobile. The same career record needs different navigation and focus patterns on a phone.

## The profile flow

The profile should support four recurring modes of work:

1. **Orient:** understand the shape of a career, current direction, and what needs attention.
2. **Explore:** move from a role or project into connected evidence, skills, and source material.
3. **Capture:** add a thought, achievement, metric, or source with little interruption.
4. **Develop:** return to raw material and make it clearer, better connected, and more useful for future assessment or writing.

These modes matter more than a fixed list of screens. A user may enter from any one of them.

## Desktop and mobile are complementary

### Desktop

Desktop is suited to orientation and exploration across several pieces of context at once.

- A user can see a career map, filters, linked items, and a selected note together.
- Connections and backlinks can remain visible without interrupting writing.
- It supports longer editing and deliberate organisation.

### Mobile

Mobile is suited to focused reading, quick capture, and small purposeful edits.

- One primary item should hold attention at a time.
- Capture must be available from anywhere and require minimal classification.
- A user should be able to inspect a link, add a connection, or update a fact without losing their place.
- Dense relationship views should become progressive disclosure, not tiny sidebars.
- Long-form editing can exist, but should not be the only way to make the profile useful on a phone.

Mobile is not a reduced product. It is a more focused path through the same career intelligence.

## Responsive content priority

Every view should identify:

- The one thing the user is trying to understand or change.
- The minimum context needed to make that decision.
- What can be revealed only when requested.
- What action a user might reasonably take with one hand, in a short moment.

For example, a mobile role note can show the role, its key evidence, and a capture action first. Projects, linked skills, sources, and full relationship detail remain one deliberate step away.

## Open questions

- What is the mobile home for someone who wants to think about their career rather than edit a specific note?
- How should quick capture behave when the user does not know where a thought belongs?
- How do we let users navigate links on mobile without making every note feel like a maze?
- Which profile tasks must be equally good on mobile, and which are intentionally better on desktop?
- When a user is in a job assessment or document, how much profile context should be reachable without leaving that work?
